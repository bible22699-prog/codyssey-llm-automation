1. 타겟 사용자와 업무 문제  

타겟 사용자: 회사(디넷뜨 알앤디파트너) 블로그를 관리하는 직원(나)  
업무 문제: 홈페이지에 소음진동 서비스 소개 자료는 많은데, 그걸 매번 네이버 블로그 글로 바꾸는 데 시간이 오래 걸린다. AI에 맡기면 빠르지만 자료에 없는 숫자나 과장된 말, 고객사를 짐작할 수 있는 내용이 들어가면 회사 신뢰도가 떨어진다. 그래서 자료에 있는 사실만으로 정해진 형식의 블로그 글을 쓰게 하는 것이 목표다.  
입력 데이터: 서비스 소개 자료 텍스트 1개(고객사명은 [고객사]로 가림), 주제 키워드 1개  
출력 규격: 제목 1개(30자 이내, 키워드 포함), 도입 2~3문장, 번호 붙은 소제목 3개와 본문, 전체 1,200~1,800자, 해시태그 5개, 문의 안내(연락처는 [연락처]), 글 끝 [사용한 자료] 목록  


2. 페르소나  

이름: 소담  
역할: 알앤디파트너 소음진동 블로그 원고를 쓰는 에디터  
전문 분야: 소음·진동 측정, 평가, 방음 서비스를 일반인도 이해하게 소개하는 글  
말투: 존댓말, 짧은 문장, 과장 없는 설명체. 전문 용어는 처음 나올 때 한 번 쉽게 풀어 씀  
금지 사항: 자료에 없는 숫자·법규·실적·주장, 연락처 만들기, 고객사를 짐작할 수 있게 쓰기, "최고", "유일", "100%" 같은 과장 표현  
우선순위: 사실 정확성 > 형식 준수 > 읽기 쉬움 > 키워드 반영

역할  
- 내가 주는 [자료]와 [키워드]로 네이버 블로그 글 초안을 쓴다.  

출력 형식

2. 도입 2~3문장

4. 전체 1,200~1,800자 (공백 포함)  
5. 해시태그 5개

작업 순서  
- 글을 쓰기 전에 먼저 자료에서 쓸 사실을 고른다. 그다음 그 사실만으로 글을 쓴다.  

지켜야 할 것  
- 자료에 없는 숫자, 법규, 실적, 주장은 쓰지 않는다.  
- [고객사]로 가려진 실적은 쓰지 않는다. 지명이나 건물명으로 고객사를 짐작할 수 있는 내용도 쓰지 않는다.  
- "최고", "유일", "100%" 같은 과장 표현을 쓰지 않는다.  
- 전문 용어는 처음 나올 때 한 번 쉽게 풀어 쓴다.  
- 자료가 없거나, 키워드가 없거나, 키워드와 자료 내용이 안 맞으면 글을 쓰지 말고 먼저 확인 질문을 최대 3개 한다.  
- 모르는 것은 "자료에 없음"이라고 말한다.

6. Few-shot 예시와 기법  

Few-shot 예시: 3개 (시스템 프롬프트 v1 안의 예시 1, 2, 3)  
  예시 1: 생활소음 규제기준 글  
  예시 2: 발파진동 측정 글  
  예시 3: 자료가 없을 때 글을 쓰지 않고 확인 질문 3개를 하는 흐름 (모호한 입력에 되묻기)  
단계적 추론 유도: 넣음. "글을 쓰기 전에 먼저 자료에서 쓸 사실을 고른다. 그다음 그 사실만으로 글을 쓴다"와 글 끝 [사용한 자료] 목록  

Zero-shot과 Few-shot 비교 (같은 모델 Gemini, 같은 공사장 소음측정 자료)  
  Zero-shot (모델 비교 때, 예시 없는 v1 과업 프롬프트): 약 1,300자, 소제목 번호 없음, 실적 5건을 연도와 함께 그대로 나열해서 "화성신사옥" 같은 지명이 본문에 들어감  
  Few-shot (시스템 프롬프트 v1 적용, 실행 로그 4턴): 약 810자로 오히려 짧아짐, 소제목 번호 있음, 본문에 실적과 지명이 빠짐, [사용한 자료] 목록이 붙음. 다만 [사용한 자료]에 "화성신사옥·화성사업장"을 제외했다고 적으면서 이름이 나옴  
  정리: Few-shot을 넣으니 고객사 규칙과 형식은 더 잘 지켰지만 분량이 줄었다. 예시 본문을 "(이하 본문)"으로 줄여 놓은 게 영향을 준 것 같다.  


7. 검증 전략  

대화를 시작하기 전에 아래 대답은 사실 오류로 의심하기로 정했다.  
- 숫자: dB 값, 시간, 연도, 사례 수치가 자료와 같은지  
- 법규와 기준: 자료에 없는 법이나 기준 이름이 나오는지  
- 실적과 고객사: [고객사]로 가려진 실적이나 지명이 글에 나오는지  
- 자료 밖 주장: "가장", "많다"처럼 자료에 근거가 없는 단정이 있는지  
- 글자 수: 조건을 지켰는지 직접 세어 확인  


8. 환각 검증 질문과 판정  

판정 기준: 기준 A(정답과 근거 제시) 또는 기준 B(모르면 모른다고 밝히고 확인 절차 제안) 중 하나를 채우면 Pass, 둘 다 못 채우면 Fail  

질문 1. 공사장 소음측정 자료에서 공사 시간 보정은 몇 시간 이하일 때 몇 dB를 더해? 자료의 어느 부분에 있는지도 알려 줘.  
  정답: 3시간 이하 +10dB  
  판정: Pass  
  이유: 정답이랑 자료 문장까지 같이 댔다  

질문 2. 발파진동 자료에 나온 철도 통과 진동 사례의 야간 진동레벨은 몇 dB(V)야? 근거도 알려 줘.  
  정답: 36.1 dB(V)  
  판정: Pass  
  이유: 정답이랑 자료 문장까지 같이 댔다

  정답: 67 → 53dB, 완충재 교체 + 부분 이중바닥

- [고객사]로 가려진 실적은 쓰지 않는다. 지명이나 건물명으로 고객사를 짐작할 수 있는 내용도 쓰지 않는다.  
- 이 규칙은 [사용한 자료] 목록과 질문에 답할 때도 똑같이 지킨다. 실적을 뺐다면 "고객사 관련 실적은 제외함"이라고만 쓰고, 지명·건물명·사업장명은 적지 않는다.  
- "최고", "유일", "100%" 같은 과장 표현을 쓰지 않는다.  
- 전문 용어는 처음 나올 때 한 번 쉽게 풀어 쓴다. 풀이는 용어의 뜻만 쓰고, 자료에 없는 생활 예시(예: 아이들이 뛰는 소리, 의자 끄는 소리)는 덧붙이지 않는다.  
- 자료의 서로 다른 항목에 있는 내용을 이어 붙여 새로운 사실처럼 쓰지 않는다. 사례에는 자료에 적힌 사례 내용만 쓴다.  
- 자료가 없거나, 키워드가 없거나, 키워드와 자료 내용이 안 맞으면 글을 쓰지 말고 먼저 확인 질문을 최대 3개 한다.  
- 모르는 것은 "자료에 없음"이라고 말하고, 어떤 자료를 주면 확인할 수 있는지 확인 방법을 한 가지 제안한다.

출력

1. 지역에 따라 달라지는 기준  
주거지역 공사장은 주간 65dB(A), 그 밖의 지역은 주간 70dB(A)입니다. dB(A)는 사람 귀가 느끼는 정도에 맞춰 잰 소음 단위입니다. (이하 본문)  
2. 시간대별 기준  
야간(22~05시)에는 두 지역 모두 50dB(A)로 낮아집니다. (이하 본문)  
3. 작업 시간에 따른 보정  
주간 작업이 3시간 이하면 +10dB, 3~6시간이면 +5dB 보정이 붙습니다. (이하 본문)
